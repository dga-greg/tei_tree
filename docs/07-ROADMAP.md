# 7. Implementation Roadmap

| Phase | Scope | Key deliverables | Exit criteria |
|---|---|---|---|
| **1 — Foundation** ✅ | Monorepo, shared contracts, Express API skeleton, MongoDB + Redis wiring, all collection schemas, authentication, RBAC, platform admin (accounts), Angular shell + auth pages | See [PHASE1.md](PHASE1.md) | Auth + RBAC integration tests green against a real MongoDB replica set; frontend builds and unit tests pass |
| **2 — Family registry** ✅ | Create/update family, founding ancestor, person CRUD with fuzzy dates and privacy redaction, relationship CRUD with integrity rules (cycle check, duplicate edges, 2 biological parents), search tokens + phonetic search | See [PHASE2.md](PHASE2.md) | Integration tests for every integrity rule; redaction tests per role |
| **3 — Generation engine** ✅ | Engine (§4), recalculation job, conflict review + override, snapshots, generation dashboard + filters, family dashboard charts | See [PHASE3.md](PHASE3.md) | Unit tests incl. cousin-marriage conflicts, unknown parents, adoptive policy, founder change |
| **4 — Interactive tree** ✅ | Graph-window endpoints, family-unit layout, D3 canvas, expand/collapse, search & focus, ancestor/descendant highlight, filters, full screen, export, branches | See [PHASE4.md](PHASE4.md) | Layout unit tests (blended families, multiple partners), Playwright smoke on 5 000-person fixture |
| **5 — Relationship finder** ✅ | LCA, kinship classification, affinal/step paths, path visualisation | See [PHASE5.md](PHASE5.md) | Kinship unit tests table-driven over ≥ 40 cases |
| **6 — Collaboration** ✅ | Invitations (e-mail, expiring tokens), account linking, profile claims, contributions + review workflow, audit log viewer, restore, e-mail verification, membership/role management | See [PHASE6.md](PHASE6.md) | Integration tests for approve → apply → recalc → audit |
| **7 — Archive** ✅ | Media upload (S3-compatible, sniffing, image re-encoding, signed URLs), stories, oral histories, events timeline | See [PHASE7.md](PHASE7.md) | Upload security tests |
| **8 — Hardening & deployment** ✅ | Performance tests, security review, data export (JSON + GEDCOM) and deletion workflows, abuse reports, responsive polish, Playwright E2E suite (§19), Dockerfiles, CI/CD | See [PHASE8.md](PHASE8.md) | E2E suite green in CI |

## Second roadmap — features after the first release

| Phase | Scope | Key deliverables | Exit criteria |
|---|---|---|---|
| **9 — Bringing data in & keeping it clean** ✅ | GEDCOM import; finding and merging duplicate people | See [PHASE9.md](PHASE9.md). Upload a `.ged` file → preview (people, links, problems, likely duplicates of people already in the family) → import in one transaction, recorded in the change history and reversible as a batch. Duplicate finder (names, phonetics, dates, parents) and a merge screen that chooses field by field and moves links, photos, stories and claims to the kept person | Round trip: export → import gives the same people and links; GEDCOM files from Ancestry, MyHeritage, FamilySearch and Gramps fixtures import; merge keeps every link and archive item, and is undoable |
| **10 — Calendar, reminders & phone app** ✅ | Family calendar; reminders; installable web app with notifications | See [PHASE10.md](PHASE10.md). Calendar of birthdays, wedding anniversaries, remembrance days and family events, respecting privacy; per-person notification settings; weekly e-mail digest ("this week in the family"); the web app installable on phones (manifest, service worker, offline shell) with web push notifications | Calendar respects living-person privacy; digest job is idempotent; installable and Lighthouse PWA checks pass |
| **11 — Lineage & family life** ✅ | Clan and lineage; ceremonies; family contributions | See [PHASE11.md](PHASE11.md). *Abusua* (mother's line), *ntoro* (father's line), clan, totem and hometown on people, with inheritance down the right line and lineage views in the tree; ceremonies (naming/outdooring, engagement, wedding, funeral, one-week, anniversary) with programme, roles, photos; contributions and dues per fund, with totals per branch, visible to administrators and treasurers | Lineage follows the configured line through adoption rules; contribution totals reconcile; treasurer role tested in the permissions sweep |
| **12 — Richer archive** ✅ | Places and map; tagging people in photos; recording transcripts | See [PHASE12.md](PHASE12.md). Places as records (town, region, country, coordinates) linked to births, deaths, homes and events, shown on a map and as migration paths; tagging faces in photos by drawing a box and naming the person; transcripts for recordings and videos — typed by hand or produced by a configurable speech-to-text service — searchable, with optional translation | Map works without a tile service (list fallback); tags follow merges and deletions; transcripts are searchable and private as their recording |
| **13 — Accounts** ✅ | Two-step sign-in; sign in with Google | See [PHASE13.md](PHASE13.md). Authenticator-app codes (TOTP) with recovery codes, required for platform administrators and optional for everyone else; Google sign-in linked to existing accounts by verified e-mail | Brute-force and replay tests for codes; account takeover via Google linking is impossible without a verified address |
| **14 — Family book & languages** ✅ | Printable family book; translations | See [PHASE14.md](PHASE14.md) and [I18N.md](I18N.md). A PDF book chosen by branch or person: cover, tree, a page per person with photo, dates and stories, the timeline and photo pages; the interface translated (English, French, with Twi, Ga, Ewe and Hausa drafts for native speakers to review) and a per-person language setting | Book renders a 500-person family; every screen is translated with no missing keys |
