# Translating the interface

The app is written in English. Every text the app shows is looked up, by its English wording, in the catalog of
the chosen language (`frontend/public/i18n/<code>.json`). A text without a translation shows in English. The
language is settled before the app starts (from the account, else this device, else the browser), and changing it
reloads the app.

Languages: English (source), French, and drafts in Twi, Ga, Ewe and Hausa that wait for native speakers to review
them. See `frontend/src/app/core/i18n/languages.ts`.

## Writing translatable code

| Where | How |
|---|---|
| Template text | `{{ 'Save changes' \| t }}` — add `TranslatePipe` (`core/i18n/translate.pipe`) to the component's `imports` |
| Text with values | `{{ 'Signed in as {name}' \| t: { name: user.displayName } }}` — never glue sentences together from pieces, so translators can reorder words |
| Counts | ICU plural: `{{ '{count, plural, one {# person} other {# people}}' \| t: { count: n } }}` — never `n === 1 ? 'person' : 'people'` |
| Attributes | `[attr.aria-label]="'Close' \| t"`, `[placeholder]="'e.g. Kumasi' \| t"`, `[title]="'…' \| t"`, `[label]="'Name' \| t"` |
| Apostrophes | Use double quotes in interpolations: `{{ "Can't scan it?" \| t }}`. In attribute bindings, move the text to the class: `protected readonly hint = t("Can't scan it?")` |
| Code (messages, dialogs) | `import { t } from '…/core/i18n/i18n'`, then `t('Saved.')`, `t('Removed {name}.', { name })` — at render or event time |
| Constants made when code loads (menus, option lists, `*_LABELS`) | `mark('Dashboard')` at definition, then `{{ item.label \| t }}` where shown. Never call `t()` at module level: the language is not loaded yet |
| Labels from `@fh/contracts` (`EVENT_KIND_LABELS`…) | Show with `\| t`: `{{ kindLabels[e.kind] \| t }}`; they are extracted automatically |
| Dates | `formatFuzzyDate` from `shared/format` (not from `@fh/contracts`), Angular's `date` and `number` pipes (they follow the language) |
| Messages from the API | Shown as they come; `ApiError` translates fixed messages the catalog knows |
| Not words (symbols, sample data, names of things) | Leave as is; if the lint complains, add `<!-- i18n-ignore -->` on that template line |

Keep English wording exactly as it was when marking existing text: tests and accessibility names match it.

## Tools (in `frontend/`)

- `npm run i18n:extract` — collects every marked text (plus contract labels and the API's fixed messages) into
  `src/i18n/keys.json`.
- `npm run i18n:check` — fails when a catalog lacks a text, or a translation's `{placeholders}` differ from the
  English. Runs in CI.
- `npm run i18n:lint` — lists English text in templates that is not marked.

## Adding or reviewing a language

1. Add it to `LANGUAGES` in `core/i18n/languages.ts`, with its CLDR locale for dates and numbers.
2. Copy `public/i18n/fr.json` to `public/i18n/<code>.json` and translate the values. Never change the keys, and keep
   `{name}`-style placeholders and the `{count, plural, …}` structure. Only the words inside the plural branches
   change, and `#` stands for the number.
3. Run `npm run i18n:check`.
4. When native speakers have reviewed a draft, change its `status` to `complete`.
